# Integration Sequence

- Status: Proposed sequence only
- Prohibited now: merging PRs #30-#40, deleting or rewriting their source documents, production work, participant work, or adapter execution

## Objective

Reconcile the ten unmerged research branches into a reviewable foundation later, without allowing downstream UX or business language to redefine evidence, rights, capability, safety, privacy, or consent.

## Preconditions

1. Founder reviews the canonical ownership and decision register.
2. ChatGPT reviews this Phase 4 package and the correction to draft MVE instruments.
3. Each relevant specialist pack receives a scoped decision; silence is not approval.
4. Every retained source has an immutable commit/path and a provenance note.
5. The future integration operation has its own branch/PR and approved file-level plan.
6. No unresolved conflict is resolved by wholesale branch merge order alone.

## Proposed Order

Retain this index, conflict matrix, sequence, and register as the control plane. Freeze source SHAs and classify every later change as retain, amend, supersede, or historical.

Gate: founder and ChatGPT accept the ownership model. Rollback: withdraw the sequence; source branches remain untouched.

Gate: source paths/commits, score history, review deductions, and supersession reasons remain traceable.

## Future File-Level Method

The later integration PR should use file-level reviewed copies or purpose-built canonical documents, not merge all branch histories blindly. For each source file it must record:

- immutable source commit/path;
- owner and reviewer;
- retained sections;
- amended sections and rationale;
- superseded sections;
- destination path;
- links to historical source;
- unresolved conflicts;
- verification performed.

No source branch should be deleted merely because its content is integrated.

## Dependency Order

```text
Evidence (T02) -------> Pathway / product / impact
Rights (T03) --------> Pathway / stories / learning
Capability (T01) ----> PLC (T07) ----> Modes (T05) ----> UX (T10)
Community safety (T04) -------------------------------> UX later horizons
Plan/pathway (T06) -----------------------------------> UX MVE
Ecosystem (T08) -----> Economics (T09) --------------> UX future horizons
```

T07 may define the base contract before adapter evidence exists, but it cannot fill T01 capability fields. T10 may prepare wireframes before approval, but cannot establish upstream truth.

## Stop Rules

Stop the affected integration step when:

- a canonical owner is disputed;
- exact rights or provenance are unclear;
- a specialist identifies a Critical or High defect;
- a field would be populated by inference rather than evidence;
- participant-facing material lacks ethics/safety/privacy/accessibility review;
- a platform claim lacks a named version and test plan;
- integration would erase score, assumption, risk, or review history;
- a downstream artifact weakens an upstream safety/privacy/consent rule.

## Exit Strategy

If the integration approach fails, keep PRs #30-#40 Draft and unmerged, preserve this conflict record, and restart only the disputed file-level decision. No user, system, or production state depends on this documentation branch.
