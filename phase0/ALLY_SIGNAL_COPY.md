# Ally Signal Copy Prototype

The ally system should support the user without turning the ally into a police officer. The default model is minimal disclosure.

## Signal Levels

### Green

No action needed. The user is following their plan or has not requested support.

### Yellow

Elevated risk. The user does not need direct contact unless you agreed otherwise.

Suggested ally response if contact is pre-agreed:

"Thinking of you. No need to explain anything. Want a 3-minute reset call?"

### Red

The user hit a high-risk loop or requested help.

Suggested ally response:

"I am here. No shame. Stand up, drink water, and call me for 3 minutes if you can."

### Tamper

The user attempted to disable a protection they previously chose to protect.

Suggested ally response:

"I got a protection-change alert. I am not asking for details. Do you want help getting through the next 10 minutes?"

### Help Request

The user explicitly asked for contact.

Suggested ally response:

"I can stay with you for a few minutes. You do not have to explain. What is the next smallest safe action?"

## Ally Boundaries

Allies should not receive by default:

- Raw browsing history.
- Explicit content.
- Screenshots.
- Private notes.
- Search terms.
- Sexual details.

Allies should receive:

- What the user consented to share.
- What action is requested.
- How to respond without shame.
- How to avoid interrogation.

## Weekly Truth Session Template

Use this only if the user wants recurring accountability.

1. What worked this week?
2. What was difficult?
3. Did any protection feel too strict?
4. Did any protection feel too weak?
5. What is one rule to adjust?
6. What is one supportive thing the ally can do next week?

## Interview Questions

1. Would this amount of information help?
2. Would you need more detail?
3. Which message feels supportive?
4. Which message feels fake, controlling, or too soft?
5. What would prevent ally burnout?
