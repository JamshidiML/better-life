# Phase 0 Risk Register

This register should be updated after every 5 interviews.

| ID | Risk | Severity | Current mitigation | Open question |
| --- | --- | --- | --- | --- |
| R01 | Product increases shame after lapse | High | Use repair language, avoid streak reset as primary feedback | Which wording actually reduces shame? |
| R02 | Product becomes partner spyware | Critical | Minimal disclosure, consent expiry, coercion checks | How do we detect coercion reliably? |
| R03 | User treats product as therapy replacement | High | No diagnosis, escalation copy, clinician export | What thresholds trigger professional-care prompts? |
| R04 | Ally receives too much sensitive data | High | Green/yellow/red model, no raw history | What is the minimum useful signal? |
| R05 | False positives cause abandonment | Medium | Transparent appeals, calm review | What false-positive rate is tolerable? |
| R06 | False negatives create overconfidence | Medium | Do not promise prevention, layered defense | How should uncertainty be displayed? |
| R07 | Strong controls are impossible on some platforms | High | Platform-specific claims, no absolute guarantees | Which Phase 1 devices are first target? |
| R08 | App store policies block intended monitoring | High | Start with safe APIs and explicit permissions | Which features need policy review first? |
| R09 | Sensitive data breach | Critical | Local-first data, no explicit content storage | What data can be avoided entirely? |
| R10 | Co-occurring mental health crisis | Critical | Safety escalation protocol | What live-support partnerships are needed? |
| R11 | Religious/value customization amplifies shame | Medium | User-chosen language, safety review | What community modes are unsafe? |
| R12 | Tapering controls too early causes setback | Medium | Tapering criteria, user review | What signals indicate readiness? |

## Update Ritual

After every synthesis batch:

1. Add new risks.
2. Update severity.
3. Add evidence from interviews.
4. Decide if any planned Phase 1 feature should be removed or delayed.
